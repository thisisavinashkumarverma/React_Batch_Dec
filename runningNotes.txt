    React 18 Forms:     Form handling involves  using 'useState()' to track input values writing 'onChange' handles for each field handling submission via handleSubmit() function. 

    React 19 Form Enhancements:
        React 19 introduces Actions, which are asynchronous functions designed to simplify form logic. 
        Handle form submission declaratively , track pending states with 'useFormStatus' Manage form state witin 'useActionState()'
            It takes two params 
                1. Form submit handler function  to handle logic after user click on button 
                2. object to specify the intial state of form 

    Actions are async functions that handle form logic we pass them directly to the forms action attribute.

        Key features in React 19 forms 
            . Actions -> These are asynchronus functions that handle form submissions. Instead of manaully managing state and side effects, we define an action function and pass to the form. 

            . 'useActionState' -> It is a new hook been introduced in react 19, this hook tracks the state of an action (eg: loading, success, error). It replaces manual 'useState' and 'useEffect' logic form submission. 
                    - Manages state tied to an action (e.g., success/failure messages).
                    - Example: show a confirmation after form submission.
        
            . 'useFormStatus' -> 'Its a new hook been introduced from react 19, This hook provides realtime status of the form (eg: pending, submitted). It is useful for disabling buttons or showing spinners during submission.
                    - Tracks whether a form is currently submitting (pending).
                    - Useful for disabling buttons or showing loading spinners

        What Strict Mode Does (in Development)
            Strict Mode activates extra checks and warnings for the components inside it. 

                Detects Unexpected Side Effects: To help you write pure components, React intentionally double-invokes certain functions in development, such as component bodies, state initializers, and useEffect setup/cleanup functions. This helps ensure that your components are resilient to being mounted and unmounted multiple times (a behavior that can happen with future features like concurrent rendering).

                Identifies Unsafe Lifecycle Methods: It warns about the use of legacy or unsafe class component lifecycle methods like componentWillMount.

                Warns About Deprecated APIs: It flags the usage of deprecated features, such as the legacy string ref API, the legacy context API, and findDOMNode.

                Ensures Reusable State: it simulates a component being unmounted and remounted immediately to verify that state is properly restored and effects are cleaned up correctly. 
                
                By using Strict Mode, you can catch bugs early in development and write more robust, future-proof code that adheres to React's best practices.

useContext() -, createContext()

    useContext() is a predefined hook been supported  in react, useing which we could able to access / subscribe the context memory directl within  the functional component. 

    It works with a cotex object created using React.createContext()

    Context memory is a special memory of every component, which can be accessable only to other child components. 

    Note: The context memory will not be created for every component by default. 


    Steps to create context memory within a component

        var contextName = createContext(null); // Create a context memory

    Step 2: Define scope of context memory

        <Contextname.provider>
            <ChildComp></ChildComp>
        </Contextname.provider>

    Step 3: Accessing context memory data under child 
        let obj = useContext(contextname);

    ".Provider" : In react Provider is a special component that comes with every object 
    created using React.createContext();
        Its used to provide a value to all components inside its tree, so they can access
    that value via "useContext" without prop drilling 
        '.Provider' is essentially the gateway for passing data down the component tree. 

    Note: adding ".Provider" is  optional from Latest REact 

    Note:
        1. By default none of component holds context memory 
        2. Context memory only gets created by using createContext()
        3. We can create multiple context memory for a single compnent
        4. yes child components can access data from diff context memory, through useContext("contextname")

React Routing 
react-router-dom(V7) is the standard library for implementing dynamic, client-side routing in React web applications

 Routing enables us to create Single-Page Applications (SPAs) where navigation occurs without a full page reload. 

Core components and hooks been supported in react-router-dom lib :

<BrowserRouter>	Wraps the entire application to enable routing functionality using the browser's History API.

<Routes>	A container component that looks through its children <Route>s and renders the first one that matches the current URL.

<Route>	Defines a mapping between a specific URL path and the element (component) that should be rendered when that path is matched.

    <Route path="/" element={<Home />} />


<Link>	Used for navigation between different routes. It's a replacement for the HTML <a> tag that prevents full page reloads.

useNavigate()	A hook used for programmatic navigation, such as redirecting a user after a form submission or login.

useParams()	A hook that allows access to dynamic segments of the URL (e.g., :id in /user/:id).

<Outlet>	Used in parent routes to specify where the child routes should be rendered, enabling nested layouts.

Higher order components: 
In React, a Higher-Order Component (HOC) is an advanced pattern used for reusing component logic. It is not a part of the React API, per se, but rather a pattern that emerges from React's compositional nature.

At its core, an HOC is a function that takes a component and returns a new component. HOC is not actually a component instead it is function. 

The Basic Concept
Think of an HOC as a "wrapper" that injects extra functionality, data, or styling into an existing component without modifying the original component's code.

How it Works
The syntax usually looks like this:

JavaScript
const EnhancedComponent = higherOrderComponent(WrappedComponent);

Key Characteristics:
Pure Functions: An HOC should be a pure function with no side effects. It shouldn't modify the input component; it should use composition.

Logic Reuse: Great for handling repetitive tasks like fetching data, checking authentication, or logging analytics.

React Fiber: 
React Fiber is the reimplementation of React’s core reconciliation algorithm introduced in React 16, designed to make rendering smoother, more flexible, and capable of handling complex UI updates like animations and gestures. Its key innovation is incremental rendering, which allows React to break work into chunks and prioritize updates for better responsiveness.

- Definition: React Fiber is the new reconciliation engine in React, replacing the older stack-based algorithm.
- Introduced: In 2017 with React 16.
- Purpose: To improve responsiveness and enable advanced features like concurrency, prioritization, and interruption of rendering tasks

Core Features
- Incremental Rendering: Breaks rendering work into units and spreads them across frames, keeping the UI responsive.
- Prioritization: Assigns priority to updates (e.g., user input > background data fetching).
- Interruptible Work: Rendering can be paused, aborted, or reused when new updates arrive.
